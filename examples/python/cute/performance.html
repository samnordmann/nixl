Performance evidence, not a speed-of-light assertion

September 30, 2026. This follow-up replaces one-thread copying and host-synchronized steady-state exchanges with cooperative NIXL calls and GPU receive credits. The design walkthrough explains the ordering/lifetime contract; the README contains commands.

What is compared

benchmark.py measures a complete padded all-to-all, including self-copy, destination reuse credits, outgoing PUT completion, publication and incoming readiness. CuTe is compared with an independent NVCC implementation of the same protocol and, optionally, PyTorch/NCCL all_to_all_single. The native comparison isolates integration overhead; NCCL provides another algorithm, not equivalent elastic membership semantics.

Every implementation uses the same buffers, BF16 payload shape, stream, warmup and graph timing procedure. Inputs are nonuniform; buffers and data are reused intentionally. Two untimed exchanges inside the captured graph absorb host launch skew before CUDA timing events. Three warmup replays precede seven timed replays of 100 exchanges; the result is the median of the slowest-rank time per trial. Setup, compilation and graph capture are excluded. Full per-rank samples are emitted as JSON.

Qualified configuration

One Lyris node, four NVIDIA GB200 GPUs connected by NVLink. NVIDIA PyTorch 26.06, CUDA 13.3, CUTLASS DSL 4.5.1, LLVM 20, installed UCX 1.21.0. Host NIXL and device bitcode use the same UCX headers. The installed UCX configuration has --without-gda: the qualified transport is CUDA-IPC, not RDMA.

Choices retained and rejected

  • Expose native cooperation levels, descriptor indices, channels, deferred submission and explicit progress/completion. A wrapper must not force every request to complete immediately.
  • Use one ready counter and one credit counter per peer, not an atomic for every tile. Kernel completion joins all tile writers before publication.
  • Precompile launchers, preallocate application buffers, and advance sequence numbers on the GPU. There are no CPU barriers or status readbacks inside a prepared forward call.
  • Retain the one-CTA path only for small one-peer exchanges. Multi-peer serial fusion and warp-per-peer experiments did not consistently improve latency and were removed.
  • Use a configurable size-dependent tile starting point. Geometry sweeps showed that a single fixed small tile performs poorly on large slabs; this is not a general autotuner.

Correctness and limits

The checks include changing payloads, partial tiles, THREAD/WARP/BLOCK cooperation, sparse membership, contraction/rejoin, graph replay, stale Python plans, wrong-stream rejection, request state transitions and MoE golden results. The mock backend exercises pending/error transitions in the actual shim, but does not qualify transport ordering.

Small-message latency can still trail native NIXL and NCCL. Native parity at bandwidth-sized messages is not a proof of universal speed of light. True pending RDMA overlap, cross-node publication ordering, late process creation, crash recovery, Hopper and real FFN/MoE throughput are not established by these tests.

Elasticity here means graceful changes among registered standby processes, with stable IDs and per-epoch peer views. The binding adds no communicator requirement, but the teaching control plane still uses a fixed Gloo world. Routing/padding and multiplication experts are not production MoE kernels.

Reproduce

nvcc -std=c++17 -O3 -DNDEBUG -arch=sm_100 -shared -Xcompiler -fPIC \
  -I src/api/device -I src/api/cpp -I /opt/hpcx/ucx/include \
  test/python/cute_native_reference.cu -o /tmp/cute_native_reference.so
timeout 180s torchrun --standalone --nproc-per-node=4 \
  examples/python/cute/benchmark.py --bytes 67108864 \
  --reference-so /tmp/cute_native_reference.so --nccl

Use --tile-bytes, --threads and --level to sweep geometry. Use an external timeout: this prototype deliberately has no device-wait failure recovery. Compare only runs with matching topology, compiler, backend and graph settings.
